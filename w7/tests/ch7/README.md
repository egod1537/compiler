# 과제7 시멘틱 분석기 테스트

이 디렉터리는 과제7 전용 49개 테스트와 기존 과제6 입력 47개의 회귀 실행을
담당한다. 과제7 테스트의 목적, 기대 결과, 필수 진단과 AST 확인 항목은
`manifest.json`에 고정되어 있다.

## 구성

| 분류 | 개수 |
|---|---:|
| 변수 선언 및 초기화 (`variables`) | 7 |
| 배열 및 포인터 (`arrays`) | 13 |
| 구조체·공용체·enum (`aggregates`) | 6 |
| 수식 및 형변환 (`expressions`) | 7 |
| 함수 (`functions`) | 6 |
| 명령문 (`statements`) | 7 |
| 리터럴 테이블 (`literals`) | 3 |
| 합계 | 49 |

기대 결과 분포는 정상 24개, 오류 17개, 경고 8개다. 기존 번호는 재사용하거나
당기지 않아 과제7 목록은 TC01~TC47, TC50~TC51로 구성된다. `run.py`는 먼저
`make clean`과 `make`를 실행하며 빌드 실패 시 파서를 실행하지 않는다. 이후 각
입력을 과제 파서와 시스템 C 컴파일러(`CC`, 기본값 `cc`)에 전달하고 종료 코드,
진단, 시멘틱 AST 필수 조각, 크래시 및 타임아웃을 기록한다.

```sh
make test
# 또는
python3 tests/ch7/run.py
```

결과 파일은 `results/`에 생성된다.

- `build.log`: clean/build 전체 로그
- `test.log`: 모든 TC와 회귀 테스트의 정규화된 실행 로그
- `summary.json`: 자동 판정 및 비교 결과
- `cases.csv`: TC별 목적·기대·실제·C 컴파일러 결과·성공 여부

`RESULTS.md`는 실제 실행 결과를 바탕으로 작성한 한국어 분석 보고서다.

## 지원 범위에서 제외한 항목

교재 기반 구현의 현재 지원 범위에 맞춰 다음 입력은 테스트 소스와 실행 목록에서
제외했다.

- TC48: 하나의 `switch` 안에 같은 값의 `case`가 중복되는 경우
- TC49: 하나의 `switch` 안에 `default`가 중복되는 경우
- CH6-5-10: 불완전 구조체를 가리키는 포인터 선언

분석기는 switch별 레이블 집합을 저장하지 않으며, 전방 선언된 불완전 구조체의
포인터 사용과 완전한 객체가 필요한 사용을 구분하지 않는다. 이 세 항목을 지원
범위 밖으로 분류했으며, 컴파일러 구현과 나머지 테스트의 입력·기대 결과는 변경하지
않았다.
