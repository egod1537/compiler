# 테스트 결과

검증일: 2026-11-07

## Windows 전체 회귀

`make clean && make && make test` 결과는 기존 기능 테스트 72개와 별도의
`w4-1` 직접 비교 125개가 모두 통과했고 실패는 0개이다.

| 그룹 | 통과 | 실패 | 검증 내용 |
|---|---:|---:|---|
| CH5 | 15 | 0 | 기본 구문, 제외 문법, LF/CRLF |
| AST | 17 | 0 | 정상/오류 파서 입력 |
| ASTEXP | 7 | 0 | 선택된 기대 AST 입력 |
| SEM | 17 | 0 | 실제 `semantic.c` 의미 도우미 단위 테스트 |
| SEMERR | 16 | 0 | 실제 파서 선언 오류와 오류 분류 |
| BASELINE | 125 | 0 | `w4-1` 수용/거부 및 정상 AST 직접 비교 |

추가 검증:

- 컴파일 경고 없음
- `parser.cmd` 빌드 성공
- `tests/ch5/run.ps1`: 15개 통과, 0개 실패
- `tests/sem/run.cmd 1`: 개별 실행 성공
- `make test-semerr TEST=1`: 1개 통과, 0개 실패
- 잘못된 SEMERR 번호는 0이 아닌 종료 코드 반환
- 제공된 AST JSON 기대 그래프 7개 모두 현재 출력과 일치
- `make test-baseline`: 125개 입력 모두 `w4-1`과 일치
- 선언, 매개변수, 태그, 문장 조합으로 생성한 추가 입력 168개도 종료 코드와
  정규화된 전체 출력이 모두 일치

SEMERR에서 확인한 강의자료 오류 코드는 11, 12, 13, 14, 21, 22, 23,
26, 32이다. 정상 스코프 가림, 완성되는 구조체 전방 참조 및 일치하는 함수
원형/정의에서는 오탐이 없었다. `w4-1`과 동일하게 `void` 매개변수 목록은
오류 14와 23으로 거부한다. 별도로 Yacc 문법 오류는 `SYNTAX_ERROR`, 잘못된
문자는 `LEXICAL_ERROR`로 확인했다.
이 분류 태그는 SEMERR 러너가 `COMPILER_ERROR_TAGS=1`로 실행할 때만 켜지며,
기본 오류 출력은 `w4-1`과 동일하게 유지한다.

## 수정 과정 오류 기록

- AST PowerShell 검사기를 복구한 직후 `ast_expected.c`가 컴파일 목록에서
  빠져 링크에 실패했다. `tests/ast/check.ps1`의 테스트 전용 소스 목록에
  해당 파일을 추가했다.
- 저장 클래스 관련 단위 테스트를 과제 범위에 맞게 교체하는 과정에서
  존재하지 않는 `T_CHAR` 열거값을 사용해 컴파일 오류가 발생했다. 제공된
  `T_KIND`에 존재하는 `T_POINTER`로 바꿔 서로 다른 타입 객체 검사를 유지했다.
- 기존 테스트가 `main(void)`, `double`, `S_AUTO` 출력에 의존해 처음에는
  `w4-1`과 다르게 동작했다. 컴파일러를 테스트에 맞추지 않고 해당 확장을
  제거한 뒤 테스트 입력과 기대 그래프를 교수 코드 기준으로 수정했다.
- 최초 직접 비교에서는 109개 입력의 수용/거부와 16개 정상 AST가 모두
  일치했다. 테스트 입력을 교수 문법으로 정리하고 비교 범위를 확장한 최종
  고정 사례를 추가하기 전 `BASELINE` 검사에서는 124개가 모두 일치했고,
  최종 검사에서는 125개가 모두 일치했다.
- 첫 `BASELINE` 러너는 Bash 환경에서 `rg`를 찾지 못해 입력 0개를 성공으로
  잘못 처리했다. 입력 검색을 `find`로 바꾸고 입력이 0개이면 실패하도록
  방어 검사를 추가했다.
- 종료 코드를 정확히 비교하도록 강화한 뒤 `double value;`에서 `w4-1`은
  null 타입 역참조로 비정상 종료하지만 `w4`는 방어 코드 때문에 오류 종료해
  차이가 발견됐다. 교수 코드 동작을 우선하여 해당 방어를 제거했고 최종
  125개 종료 코드가 모두 일치했다.
- 잘못된 내장 함수 정의 `void printf(char *x, char *y) { ... }`에서도 타입
  비교 방어 코드 때문에 종료 방식이 달랐다. 교수 코드와 같은 재귀 타입 비교로
  맞추고 해당 입력을 `BASELINE` 고정 회귀 사례로 추가했다.

## Unix

동일 Makefile과 POSIX Bash 러너를 사용하며 Unix에서는 `YYSTYPE`을 64비트
`long`으로 구성한다. 로컬 WSL Ubuntu에는 GCC, Bison, Flex, Make가 설치되어
있지 않아 이 환경에서 Linux 실빌드는 수행하지 못했다.
